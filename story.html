제품 개발 이야기

현장에서 확인한 문제로 시작했습니다

공셈이는 책상에서 기획한 앱이 아닙니다. 수개월간 인테리어·건축 현장을 직접 따라다니며 시공자들과 함께 작업했고, 어디에서 시간과 비용이 새는지 눈으로 확인했습니다. 그 관찰에서 가설을 세우고, 작게 만들어 내놓고, 실제 사용 데이터로 검증한 과정을 정리했습니다.

제품 개발의 기본 루프

Problem → Hypothesis → Build → Measure → Learn

기능을 먼저 늘리지 않았습니다. 현장에서 문제를 정의하고, 거기서 검증할 가설을 세웠습니다.

PROBLEM

현장에서 시간과 비용이 새는 지점

  • 현장 기록의 취약성 · 현장 노트가 물에 젖어 계산·기록이 유실되거나, 정작 필요할 때 노트를 안 가져와 이전 내역을 확인하지 못하는 일이 잦습니다. 반면 휴대폰은 누구나 늘 소지합니다.
  • 계산·기록의 비효율 · 면적·수량·로스율 계산이 계산기·엑셀·수첩에 흩어져 있어 매번 도구를 바꿔가며 작업하고 결과를 따로 옮겨 적어야 합니다. 장갑을 끼거나 양손이 바빠 입력 자체가 번거롭고, 눈대중으로 넘어가 과부족 발주·재작업으로 이어집니다.
  • 소통·실측의 한계 · 현장은 지역 방언·은어('헤베', '사메다' 등)로 소통해 기존 AI 앱은 질문을 잘 알아듣지 못하고, 실측은 수기나 외부 스캐닝에 의존해 비용·정확도에 한계가 있습니다.
HYPOTHESIS

가설

현장 규격(면적·치수)만 입력하면 KS 규격·표준품셈 기반으로 자재 수량과 견적을 자동 산출하고, 계산·기록·상담·일정을 하나로 묶어주면, 계산 시간과 오차·손실이 줄어 작업자가 계속 사용할 것이다.

제품 개발의 기본 루프

지표를 정하고, 작게 만들어 내놓았습니다

무엇을 보고 성공을 판단할지 먼저 정한 뒤, 가장 작은 형태로 만들어 실제 현장에 내놓았습니다.

METRIC

검증 지표

가설 검증 지표로 '계산 → 작업기록 저장 전환율'과 '재사용(리텐션)'을 정했습니다. 전체 지표 체계는 아래 '지표는 세 종류로 나눠서 본다'에서 정리했습니다.

BUILD

작게 구현 · MVP

전 기능을 다 넣지 않고 핵심 자재 계산기 + 업무수첩(작업기록·메모)만 붙여 iOS·Android에 작게 출시했습니다.

  • 직접 인테리어·건축 시공현장에 나가 보고 들으며, 현장에서 실제로 쓰는 공식값을 반영해 기능을 구현했습니다.
  • 로컬 데이터 저장을 기반으로 오프라인에서도 문제없이 사용 가능하도록 설계했습니다. 현장은 인터넷이 안 되는 경우가 비일비재하기 때문입니다.
  • 유입도 유료 광고 없이(광고비 0원) SNS 릴스로 작게 검증했습니다.

Learn / Pivot

검증된 경험 위에 단계적으로 확장합니다

계산·기록 경험이 검증된 뒤에야 다음 기능을 얹습니다. 기능을 추가할 때마다 "이 기능이 목표 지표를 움직이는가?"를 먼저 묻습니다.

NOW · 추가 완료
  • 음성 AI 비서 '공담이' · 지역 방언·구어체·현장 용어까지 이해하도록 특화. 자체 LLM과 외부 LLM API를 함께 쓰는 하이브리드 구조.
  • 하이브리드 라우팅·프롬프트 캐싱으로 질의당 원가 절감, 방언 정규화·의도 분류 등은 자체 소형 LLM으로 전환 예정.
  • 글로벌 다국어 버전 · 영어 지원 출시 완료. 국내 외국인 근로자 수요에 대응합니다.
NEXT · 진행 예정
  • PC 버전 출시 26.09 예정
  • 홍보문구 자동 작성 · 네이버 블로그·인스타그램 연계로 앱에서 글·피드 자동 생성.
  • AI 견적서·업무일지 자동 작성
  • 세금계산서 발행 등 행정 업무 · 정부 사이트에 따로 들어갈 필요 없이 앱에서 처리 (정부 API 연계).
FUTURE · 개발 추진
  • 자체 공간분석·도면화 기술 · 모바일에서 취득한 공간 데이터로 벽체·바닥·천장·개구부 구조와 치수를 자동 인식하고, 실측 기반 2D 도면·3D 공간 모델로 변환.
  • 기존 외주(도면 건당 평균 약 43만 원, 3D 투시도 장당 3~5만 원) 대비 시간·비용을 크게 절감.
BEYOND · 확장 목표
  • 계산·기록에서 시작해 견적·거래·행정까지 하나로 잇는 종합 업무 플랫폼으로 확장.
  • 수출을 통한 해외 시장 확장 · 미국 야드파운드법·ASTM, 유럽 미터법·EN/유로코드, 일본 JIS 등 지역별 단위·규격 반영.
지표 체계

지표는 세 종류로 나눠서 봅니다

성장 지표만 보면 오계산·오인식 같은 예외 상황을 놓칩니다. 자재 수량을 다루는 제품이라 계산·생성 신뢰성을 별도 안전선으로 관리합니다.

Guardrail Metric

나빠지면 안 되는 안전선
  • 자재 계산 오류율
  • 음성(공담이) 방언·용어 오인식률
  • AI 홍보문구의 과장·허위 표현 발생률
  • AI 결과 과도 수정률
  • 이탈률
Guardrail이 없으면 서비스 지표(설치·사용)는 잘 나와도 엣지 케이스·예외 상황(오계산·방언 오인식·허위 홍보문구)에 대응하기 어렵습니다.
자재 수량을 다루고 자체 LLM으로 전환해가는 AI 제품에선 계산·생성 신뢰성이 특히 중요합니다.
